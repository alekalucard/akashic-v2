# Cardinal WoW Backport System

A comprehensive system for analyzing and backporting WoW retail features to AzerothCore 3.3.5a using Cardinal (Mistral via Ollama).

## Overview

The Cardinal WoW Backport System enables intelligent analysis of retail WoW spells and automatic generation of backport implementations for 3.3.5a private servers running AzerothCore.

### Key Features

- **Spell Analysis**: Compare retail spells with 3.3.5a equivalents
- **Backportability Assessment**: Determine what can/cannot be backported
- **Code Generation**: Generate Eluna Lua scripts and SQL entries
- **Learning Pipeline**: Store patterns and knowledge in SRM
- **Natural Language Queries**: Ask questions about backporting

## Architecture

```
wow_backport/
    __init__.py              # Module exports
    spell_analyzer.py        # Spell data parsing and comparison
    knowledge_manager.py     # SRM integration for learning
    backport_generator.py    # Code generation engine
    cardinal_backport_cli.py # Command-line interface
    deploy_alienware.py      # Deployment to Alienware node
```

## Usage

### CLI Commands

```bash
# Analyze a spell for backportability
python cardinal_backport_cli.py analyze 116

# Generate backport code
python cardinal_backport_cli.py backport 116

# Generate with custom spell ID (avoid conflicts)
python cardinal_backport_cli.py backport 116 --custom-id 900116

# Search for spells
python cardinal_backport_cli.py search "frostbolt" --online

# Query the knowledge base
python cardinal_backport_cli.py query "How do I backport a DoT spell?"

# Show learned patterns
python cardinal_backport_cli.py learn

# Show knowledge statistics
python cardinal_backport_cli.py stats

# Batch process multiple spells
python cardinal_backport_cli.py batch "116,133,172,403"
```

### Python API

```python
from fairies.P60_Executive.CardinalFairy.wow_backport import (
    SpellAnalyzer,
    KnowledgeManager,
    BackportGenerator,
)

# Analyze a spell
analyzer = SpellAnalyzer()
comparison = await analyzer.compare_spell(116)  # Frostbolt

print(f"Can backport: {comparison.can_backport}")
print(f"Difficulty: {comparison.backport_difficulty}")

# Generate backport code
km = KnowledgeManager()
generator = BackportGenerator(knowledge_manager=km)
result = await generator.generate_backport(comparison)

print(f"Generated {len(result.eluna_scripts)} Lua scripts")
print(f"Generated {len(result.sql_entries)} SQL files")
```

## Data Sources

### 3.3.5a DBC Files

The system can parse Spell.dbc from AzerothCore:

```bash
# Expected location
C:/AzerothCore/data/dbc/Spell.dbc
```

DBC format:
- Magic: `WDBC` (4 bytes)
- Header: record_count, field_count, record_size, string_block_size
- Records: Fixed-size binary data
- String block: Null-terminated strings

### Wowhead API

Falls back to Wowhead for spell data:
- Retail: `https://www.wowhead.com/spell=ID`
- 3.3.5a: `https://www.wowhead.com/wotlk/spell=ID`

## Generated Output

### Eluna Lua Scripts

Example output for a damage spell:

```lua
--[[
    Frostbolt Backport - Spell ID: 116
    Generated by Cardinal WoW Backport System
]]--

local SPELL_ID = 116
local SPELL_NAME = "Frostbolt"

local function OnSpellCast(event, player, spell, skipCheck)
    local spellId = spell:GetEntry()
    if spellId ~= SPELL_ID then return end

    local target = spell:GetTarget()
    if not target then return end

    target:DealDamage(target, 500, SPELL_ID)
    target:AddAura(SPELL_ID, player)
end

RegisterPlayerEvent(5, OnSpellCast)
print("[Backport] Frostbolt loaded!")
```

### SQL Entries

Example spell_dbc entry:

```sql
DELETE FROM `spell_dbc` WHERE `Id` = 900116;
INSERT INTO `spell_dbc` (`Id`, `SpellName`, ...)
VALUES (900116, 'Frostbolt (Backported)', ...);
```

### DBC Instructions

For spells not in 3.3.5a:
1. Use provided SQL (recommended)
2. Or modify Spell.dbc with MyDBCEditor
3. Or use Eluna SPELL_EVENT hooks

## Knowledge System

### Categories

- **spells**: Analyzed spell data
- **talents**: Talent information
- **classes**: Class mechanics
- **mechanics**: Game mechanic patterns
- **patterns**: Successful backport patterns
- **failures**: Failed approaches (to avoid)

### SRM Integration

Knowledge is stored in:
```
P10_Memory/Akashic_triple_helix_memory_storage/relational_clusters/Cardinal/
```

### Learning Pipeline

1. Analyze spell -> Store spell knowledge
2. Generate backport -> Store patterns used
3. Report success/failure -> Update pattern confidence
4. Future backports use learned patterns

## Engine Limitations (3.3.5a)

These retail features CANNOT be backported:

- Spell charges system
- More than 3 effects per spell
- Talent specializations
- Mythic+ affixes
- Group finder integration
- Personal loot
- Artifact weapons
- Essence/corruption/covenant systems
- Dynamic flight
- Zone scaling
- War mode / PvP talents
- Transmog collections

## Troubleshooting

### Ollama Not Responding

```bash
# Check if running
curl http://localhost:11434/api/tags

# Start if needed
ollama serve

# Pull model if missing
ollama pull mistral
```

### DBC Parse Errors

- Ensure Spell.dbc is from 3.3.5a client
- Check file is not corrupted
- Verify WDBC magic header

### Generated Code Issues

- Check Eluna API version compatibility
- Verify spell IDs don't conflict
- Test in isolated environment first
